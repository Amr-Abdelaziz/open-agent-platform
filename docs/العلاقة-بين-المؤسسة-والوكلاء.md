# العلاقة بين المؤسسة والوكلاء الذكيين

> **المشروع:** منصة الوكلاء المفتوحة — تطبيق هيئة GOEIC  
> **التاريخ:** 2026-02-21  
> **الاتجاه:** من اليمين إلى اليسار (RTL)

---

## 1. المفهوم الجوهري

المنصة تربط **الهيكل التنظيمي البشري للمؤسسة** مباشرةً بـ **وكلاء الذكاء الاصطناعي**. كل موظف يحصل تلقائياً على وكيل ذكاء اصطناعي مُخصَّص يفهم دوره الوظيفي، ويعرف سياق إدارته، ولديه الوصول إلى قواعد المعرفة الصحيحة — وكل ذلك يتم أوتوماتيكياً بناءً على مسماه الوظيفي فقط.

```
المؤسسة (من أنت؟)  →  الشخصية (كيف يتصرف وكيلك؟)  →  الوكيل (الذكاء الاصطناعي الفعلي)
```

### لماذا هذا التصميم؟

| المشكلة | الحل |
|---|---|
| كل موظف يحتاج سياقاً مختلفاً | الشخصية تُخصَّص لكل مسمى وظيفي |
| المدير يحتاج نظرة شاملة | أرشيتايب `org_manager` يرى بيانات المؤسسة الكاملة |
| الموظف التنفيذي يحتاج تفاصيل مهامه | أرشيتايب `workgroup` متخصص في نطاق عمله فقط |
| كل إدارة لديها وثائق ولوائح مختلفة | كل وكيل يحصل على مجموعات RAG مخصصة لإدارته ودوره |
| لا يجب أن يختار الموظف وكيله بنفسه | النظام يُعيّن الوكيل تلقائياً من المسمى الوظيفي |

## 2. المفتاح الرابط: المسمى الوظيفي

**`job_title`** هو الخيط الذي يربط كل شيء معاً:

```
يسجّل المستخدم دخوله
        │
        ▼
يُقرأ ملف تعريف المستخدم من قاعدة البيانات
  ├── department:  "إدارة الشؤون القانونية"
  └── job_title:   "مستشار قانوني"
              │
              ▼ (بحث عن شخصية بنفس المسمى الوظيفي)
       OrgPersona (شخصية الوكيل)
          ├── persona_text      → نص شخصية الوكيل (System Prompt)
          ├── agent_type        → نوع الأرشيتايب (workgroup في هذا المثال)
          ├── hierarchy_level   → 3 (مستوى تنفيذي)
          ├── rag_collections   → ["goeic-laws", "dept-legal", "role-counselor"]
          ├── capabilities      → ["تحليل قانوني", "مراجعة العقود"]
          └── assigned_agent_id → معرّف الوكيل في LangGraph
                    │
                    ▼
         تبدأ المحادثة مع الوكيل المُعيَّن
         مع حقن كامل السياق المؤسسي
```

## 3. نموذج البيانات الكامل

### 3.1 طبقة المؤسسة — "من أنت؟"

#### `OrganizationData` — جدول `org_core`

يحتوي على الهوية العليا للمؤسسة. صف واحد فقط في الجدول (`id = "goeic-001"`).

| الحقل | النوع | الغرض في الوكيل |
|---|---|---|
| `name_ar` / `name_en` | string | اسم المؤسسة يُضمَّن في جميع المطالبات |
| `short_name` | string | الاختصار (مثل: GOEIC) |
| `established_year` | number | سياق تأريخي |
| `parent_ministry_ar` | string | الوزارة الأم — تُحدد نطاق الصلاحيات |
| `vision_ar` | string | يُحقَن في prompt المدير التنفيذي |
| `mission_ar` | string | يُحقَن في جميع الوكلاء |
| `goals` | string[] | الأهداف الاستراتيجية — توجّه الوكلاء في الردود |
| `values` | string[] | القيم المؤسسية — تُحدد أسلوب التواصل |
| `annual_plan_summary` | string | خلاصة الخطة السنوية |
| `general_policies` | string[] | السياسات العامة — تُضاف تلقائياً لجميع الوكلاء |

---

#### `OrgDepartment` — جدول `org_departments`

كل إدارة في المؤسسة لها صف منفصل.

| الحقل | النوع | الغرض في الوكيل |
|---|---|---|
| `id` | string | معرّف الإدارة (مثل: `dept-legal`) |
| `name_ar` / `name_en` | string | اسم الإدارة — يُضاف لسياق الوكيل |
| `description_ar` | string | وصف الإدارة — يُفيد وكيل مدير الإدارة |
| `manager_title_ar` | string | مسمى الرئيس الإداري |
| `job_titles` | OrgJobTitle[] | **قائمة جميع المسميات الوظيفية بداخل الإدارة** |
| `rag_collection` | string | معرّف مجموعة RAG الخاصة بالإدارة |
| `kpis` | string[] | مؤشرات الأداء — تُحقَن في Prompt مدير الإدارة |
| `delegation_level` | 1 \| 2 \| 3 | مستوى التفويض (1=أعلى صلاحية، 3=تنفيذي) |

---

#### `OrgJobTitle` — مُخزَّن داخل `org_departments` كـ JSONB

كل مسمى وظيفي داخل الإدارة.

| الحقل | النوع | الغرض |
|---|---|---|
| `title_ar` / `title_en` | string | المسمى الوظيفي — **هذا هو المفتاح الذي يربط بالشخصية** |
| `description_ar` | string | وصف الدور الوظيفي |
| `hierarchy_level` | 1 \| 2 \| 3 | موقع الدور في الهيكل التنظيمي |
| `requirements` | string[] | متطلبات شغل الوظيفة |
| `kpis` | string[] | مؤشرات أداء خاصة بهذا الدور |

---

### 3.2 طبقة الشخصية — "كيف يتصرف الوكيل؟"

#### `OrgPersona` — جدول `org_personas`

هذا هو قلب النظام. لكل مسمى وظيفي شخصية وكيل واحدة.

| الحقل | النوع | الغرض التفصيلي |
|---|---|---|
| `job_title` | string | **المفتاح الأساسي** — يطابق `OrgJobTitle.title_ar` بالضبط |
| `persona_text` | string | نص الشخصية الكامل. يُبنى منه `System Prompt` الوكيل. مثال: *"أنت مستشار قانوني متخصص في التشريعات الجمركية..."* |
| `agent_type` | AgentArchetype | يحدد سلوك الوكيل العام (راجع القسم 4) |
| `hierarchy_level` | 1 \| 2 \| 3 | يجب أن يطابق مستوى `OrgJobTitle` المقابل |
| `department` | string | معرّف الإدارة — يربط الشخصية بإدارتها |
| `goals` | string[] | أهداف الوكيل المتخصصة لهذا الدور |
| `capabilities` | string[] | ما يستطيع الوكيل فعله (تحليل، صياغة، مراجعة...) |
| `rag_collections` | string[] | **قائمة كل مجموعات RAG** التي يصل إليها الوكيل (مستوى مؤسسة + إدارة + دور) |
| `rag_context` | string | مجموعة RAG الأساسية |
| `tools` | string[] | الأدوات المتاحة للوكيل (web search, calculator...) |
| `assigned_agent_id` | string | UUID الوكيل الفعلي في LangGraph |
| `assigned_deployment_id` | string | نقطة نهاية النشر في LangGraph |

---

### 3.3 طبقة المعرفة — "ماذا يعرف الوكيل؟"

#### `KnowledgeAsset` — جدول `org_knowledge_assets`

مجموعات RAG التي تُغذي الوكلاء بالمعرفة المؤسسية.

| الحقل | النوع | التفصيل |
|---|---|---|
| `collection_id` | string | المعرّف المستخدم في استعلامات RAG |
| `name_ar` / `name_en` | string | الاسم المقروء للمجموعة |
| `type` | enum | نوع المحتوى (انظر أدناه) |
| `scope` | `org` \| `dept` \| `role` | من يصل لهذه المجموعة |
| `department_id` | string? | إذا كان النطاق `dept`، أي إدارة تملكها |

**أنواع محتوى KnowledgeAsset:**

| النوع | الوصف | مثال |
|---|---|---|
| `official_docs` | وثائق رسمية | قرارات مجلس الإدارة، التقارير السنوية |
| `laws` | قوانين وتشريعات | قانون الجمارك، اللوائح التنفيذية |
| `internal_regulations` | لوائح داخلية | دليل الإجراءات، سياسة الموارد البشرية |
| `meeting_records` | محاضر اجتماعات | قرارات لجان الإدارة |
| `digital_registry` | السجل الرقمي | قاعدة بيانات المستوردين والمصدّرين |

**المستويات الثلاثة لمجموعات RAG:**

```
وكيل "مستشار قانوني" في "إدارة الشؤون القانونية" يصل إلى:

  مستوى المؤسسة (scope: org)
  ├── goeic-laws           → قوانين الجمارك والتجارة
  └── goeic-official       → الوثائق الرسمية للهيئة

  مستوى الإدارة (scope: dept)
  └── dept-legal           → وثائق وقرارات الشؤون القانونية تحديداً

  مستوى الدور (scope: role)
  └── role-counselor       → حالات قانونية سابقة، نماذج عقود
```

## 4. الأنماط الخمسة للوكلاء (Agent Archetypes)

كل شخصية تنتمي لأحد خمسة أنماط تحدد سلوكها الكلي:

| الكود | الاسم بالعربية | المستوى | الدور |
|---|---|---|---|
| `org_manager` | وكيل مدير المؤسسة | 1 | رؤية شاملة لكل الهيئة. يساعد في القرارات الاستراتيجية، التقارير العليا، والأهداف المؤسسية. يصل لجميع مجموعات RAG. |
| `dept_manager` | وكيل لكل إدارة | 2 | متخصص في إدارة بعينها. يعرف مهامها بعمق، أهدافها، مؤشرات أدائها، وأعضاء فريقها. يصل لمجموعات org + dept. |
| `decision_support` | وكيل مساعد اتخاذ القرار | 1-2 | يحلل البيانات ويقدم توصيات مبنية على الأدلة. يُستخدم من المديرين عند اتخاذ قرارات مهمة. |
| `compliance` | وكيل أمان وامتثال | 1-2 | يراقب الامتثال للوائح والسياسات. يضمن الالتزام بالمعايير القانونية والتشغيلية. |
| `workgroup` | وكيل مجموعة عمل مخصص | 3 | وكيل متخصص لمهمة أو مشروع أو دور محدد داخل الهيئة. الأكثر شيوعاً للموظفين التنفيذيين. |

## 5. بناء System Prompt — التفاصيل

عندما يفتح المستخدم محادثة، يُبنى `System Prompt` الوكيل أوتوماتيكياً من ثلاث طبقات:

### الطبقة 1: السياق المؤسسي العام (من OrganizationData)
```
أنت وكيل ذكاء اصطناعي تعمل باسم [اسم المؤسسة].
رسالة المؤسسة: [mission_ar]
رؤية المؤسسة: [vision_ar]
القيم المؤسسية: [values[0]]، [values[1]]، ...
السياسات العامة:
  - [general_policies[0]]
  - [general_policies[1]]
  ...
```

### الطبقة 2: سياق الإدارة (من OrgDepartment)
```
أنت مُعيَّن في: [department.name_ar]
وصف الإدارة: [department.description_ar]
المشرف المباشر: [department.manager_title_ar]
مؤشرات أداء الإدارة:
  - [kpis[0]]
  - [kpis[1]]
  ...
```

### الطبقة 3: شخصية الدور الوظيفي (من OrgPersona)
```
[persona_text الكامل]

أهدافك كـ [job_title]:
  - [goals[0]]
  - [goals[1]]
  ...

قدراتك:
  - [capabilities[0]]
  - [capabilities[1]]
  ...
```

**الكود المسؤول:** `src/lib/mock-org-data.ts` → دالة `buildOrgAwareSystemPrompt()`

## 6. تدفق البيانات الكامل من البداية للنهاية

```
┌──────────────────────────────────────────────────────────────────────┐
│  إعداد الأدمن (قبل استخدام النظام)                                  │
│                                                                      │
│  ① إعداد بيانات المؤسسة (OrgDashboard)                              │
│     - رفع الرؤية، الرسالة، القيم، الأهداف                           │
│     - إضافة الإدارات والمسميات الوظيفية                              │
│                                                                      │
│  ② إنشاء الأصول المعرفية (KnowledgeAssets)                          │
│     - رفع الوثائق إلى قاعدة البيانات Storage                              │
│     - تحديد نطاق كل مجموعة (org / dept / role)                      │
│                                                                      │
│  ③ إعداد شخصيات الوكلاء (PersonaManagement)                         │
│     - كتابة persona_text لكل مسمى وظيفي                             │
│     - اختيار الأرشيتايب المناسب                                     │
│     - ربط مجموعات RAG بكل شخصية                                     │
│     - تعيين وكيل LangGraph لكل شخصية                               │
│                                                                      │
│  ④ حفظ كل شيء في قاعدة البيانات عبر org-api.ts                           │
└──────────────────────────────────────────────────────────────────────┘
                              ↓ حفظ في قاعدة البيانات
┌──────────────────────────────────────────────────────────────────────┐
│  تسجيل دخول المستخدم                                                 │
│                                                                      │
│  ① تسجيل الدخول عبر قاعدة البيانات Auth                                   │
│                                                                      │
│  ② fetchMyProfile(accessToken)                                       │
│     → يُعيد: { department: "...", job_title: "..." }                │
│                                                                      │
│  ③ OrganizationProvider يُحمّل جميع بيانات المؤسسة من قاعدة البيانات      │
│     (يحدث مرة واحدة عند تحميل التطبيق)                              │
│                                                                      │
│  ④ getPersona(job_title)                                             │
│     → يُعيد OrgPersona المطابقة                                      │
│     → إذا لم توجد شخصية: يُعرَض للمستخدم رسالة "لا يوجد وكيل مُعيَّن" │
│                                                                      │
│  ⑤ injectPersona(persona.assigned_agent_id, profile)                │
│     → buildSystemPrompt() يبني السياق الكامل (طبقات 1+2+3)          │
│     → getUserRagCollections() يجمع مجموعات org + dept + role        │
│     → updateConfig() يُحقن كل شيء في إعدادات الوكيل                │
│                                                                      │
│  ⑥ تبدأ المحادثة مع الوكيل المُخصَّص والسياق المؤسسي الكامل         │
└──────────────────────────────────────────────────────────────────────┘
```

## 7. منطق تعيين المستخدمين للوكلاء

### المستخدم العادي (غير الأدمن)
- ❌ **لا يمكنه** اختيار وكيله بنفسه
- ✅ يُعيَّن تلقائياً للوكيل المرتبط بمساه الوظيفي
- ⚠️ إذا لم توجد شخصية لمسماه الوظيفي → يرى إشعاراً ولا يمكنه بدء محادثة

### المستخدم الأدمن
- ✅ يمكنه الوصول لـ `OrgDashboard` وتعديل كل البيانات
- ✅ يمكنه إدارة الشخصيات من `PersonaManagement`
- ✅ يمكنه رؤية الهيكل التنظيمي الكامل مع المستخدمين الحقيقيين عبر `HierarchyView`
- ✅ يمكنه تعيين أي وكيل لأي شخصية يدوياً

## 8. خصائص الأمان (RLS)

تم تفعيل **Row Level Security** على جميع جداول المؤسسة في قاعدة البيانات:

| السياسة | يُطبَّق على | الوصف |
|---|---|---|
| `authenticated_read` | جميع الجداول | أي مستخدم مُصادَق عليه يمكنه القراءة |
| `service_role_write` | جميع الجداول | الكتابة والتعديل والحذف فقط عبر service role |
| منطق التطبيق | طبقة الـ API | التحقق من صلاحيات الأدمن قبل السماح بالتعديل |

## 9. مثال عملي كامل: "مستشار قانوني"

### الوضع:
- إدارة: **إدارة الشؤون القانونية**
- مسمى وظيفي: **مستشار قانوني**

### بيانات `OrgDepartment`:
```json
{
  "id": "dept-legal",
  "name_ar": "إدارة الشؤون القانونية",
  "manager_title_ar": "مدير الشؤون القانونية",
  "rag_collection": "dept-legal",
  "kpis": ["نسبة حل النزاعات", "عدد العقود المُراجَعة"],
  "job_titles": [
    {
      "title_ar": "مستشار قانوني",
      "hierarchy_level": 3,
      "description_ar": "متخصص في التشريعات الجمركية والتجارية"
    }
  ]
}
```

### بيانات `OrgPersona`:
```json
{
  "job_title": "مستشار قانوني",
  "agent_type": "workgroup",
  "hierarchy_level": 3,
  "department": "dept-legal",
  "persona_text": "أنت مستشار قانوني متخصص في التشريعات الجمركية والتجارية...",
  "goals": ["تقديم رأي قانوني سليم", "مراجعة العقود والاتفاقيات"],
  "capabilities": ["تحليل قانوني", "صياغة عقود", "استشارة تشريعية"],
  "rag_collections": ["goeic-laws", "goeic-official", "dept-legal"],
  "assigned_agent_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
}
```

### الـ System Prompt المُولَّد تلقائياً:
```
أنت وكيل ذكاء اصطناعي تعمل باسم الهيئة العامة للتصدير والاستيراد (GOEIC).

رسالة الهيئة: تنظيم وتطوير منظومة الاستيراد والتصدير...
رؤية الهيئة: أن تكون مرجعاً رائداً...
القيم المؤسسية: النزاهة، الكفاءة، الشفافية، التميز

السياسات العامة:
  - الالتزام بالتشريعات والقوانين المعمول بها
  - الحياد التام في تقديم المعلومات

أنت مُعيَّن في: إدارة الشؤون القانونية
وصف الإدارة: تتولى الشؤون القانونية النظر في...
مؤشرات أداء الإدارة:
  - نسبة حل النزاعات
  - عدد العقود المُراجَعة

أنت مستشار قانوني متخصص في التشريعات الجمركية والتجارية...

أهدافك:
  - تقديم رأي قانوني سليم
  - مراجعة العقود والاتفاقيات

قدراتك: تحليل قانوني، صياغة عقود، استشارة تشريعية
```

## 11. جداول قاعدة البيانات (قاعدة البيانات)

| الجدول | المفتاح الأساسي | الوصف | النوع |
|---|---|---|---|
| `org_core` | `id` | صف واحد للمؤسسة (`goeic-001`) | بيانات نصية + مصفوفات |
| `org_departments` | `id` | صف لكل إدارة، يحتوي على `job_titles` كـ JSONB | مع علاقة `org_id` |
| `org_personas` | `(org_id, job_title)` | شخصية واحدة لكل مسمى وظيفي | مفتاح مركب |
| `org_knowledge_assets` | `collection_id` | صف لكل مجموعة RAG | مع علاقة `org_id` |

## 12. ملخص المصطلحات

| بالعربية | بالإنجليزية | المعنى |
|---|---|---|
| المؤسسة | Organization | الكيان التنظيمي الكامل |
| الإدارة | Department | وحدة وظيفية داخل المؤسسة |
| المسمى الوظيفي | Job Title | **الرابط الأساسي** بين الإنسان والوكيل |
| الشخصية | Persona | إعدادات سلوك الوكيل الذكي |
| الوكيل | Agent | الذكاء الاصطناعي الفعلي (LangGraph) |
| الأصل المعرفي | Knowledge Asset | مجموعة RAG تُغذي الوكيل بالمعرفة |
| حقن الشخصية | Persona Injection | تلقيم الوكيل بالسياق المؤسسي عند الدخول |
| المطالبة النظامية | System Prompt | التعليمات الأولية التي تُشكّل شخصية الوكيل |

> **الفكرة المحورية:** المؤسسة ليست مجرد بيانات ثابتة — إنها **طبقة الإعداد** لجميع الوكلاء الذكيين. تغيير الهيكل التنظيمي يعني مباشرةً تغيير كيفية تصرف الوكلاء مع كل موظف في ذلك الدور.
